\begin{abstract}
Recurrent sequence models keep a fixed-size state, so when a sequence holds
more key-value associations than the state can carry, new writes degrade old
ones. Recent work adds a bounded memory beside the state with a rule for what
to admit, driven by input novelty, prediction residual, or position. This paper
asks whether a learned write controller that also measures \emph{interference},
the conflict between an incoming association and the ones already stored,
allocates a fixed slot budget better. We build a gated-linear-attention
backbone with a bounded slot memory, a learned controller with per-slot
interference features, two ablations of it, and four rule-based writers, all
sharing one backbone, budget, and data, and test them on multi-query
associative recall with key updates and distractors across 64 and 128
associations and 32, 64, and 128 slots, three seeds per cell, paired on
identical test sequences. Neither hypothesis holds. A parameter-free rule that admits every
key-value pair and nothing else beats every learned writer in every cell, by
6.6 points at 64 associations and 64 slots; the controller does beat the
proposal's own three baselines, by 20 to 63 points above 32 slots, but H1 is
defined against the strongest baseline and that is the rule. An ablation whose gate sees nothing derived from the stored memory
matches the controller's best ablation and beats the controller at both
decisive budgets, so the interference signal carries nothing a learned gate
can use here. Three findings explain why: the 32-slot cell is capacity-bound
for any writer (the pair-only rule answers 40\% there by a closed form and no policy can exceed 50\%); the controller under-admits pairs,
which the admission statistics measure directly; and on a task whose queries
are uniform over keys, stored content cannot predict reuse, which the online
caching literature predicts. A pilot with skewed keys, where reuse is
predictable, shows the gate learns to reject distractors on two of three seeds and
still trails the rule. We provide the capacity-ceiling analysis and the pair-only reference as a
bar for learned admission policies.
\end{abstract}

\section{Introduction}
\label{sec:intro}

\subsection{The problem}

A Transformer remembers everything it has seen because its key-value cache grows
with the sequence~\cite{vaswani2017attention}. Recurrent alternatives, including
linear attention~\cite{katharopoulos2020linear}, gated linear
attention~\cite{yang2023gla}, DeltaNet~\cite{yang2024deltanet}, and selective
state space models~\cite{gu2023mamba}, replace the cache with a state of fixed
size. That makes inference cost constant per token, but it also makes memory a
scarce resource. When a sequence contains more associations than the state can
hold, a new write lands on directions already in use and the old association
degrades. Zoology~\cite{arora2023zoology} made this concrete with the multi-query
associative recall (MQAR) task, where recall accuracy of fixed-state models falls
off as the number of key-value pairs grows past the state's capacity. A recent
mechanistic study~\cite{lee2026howlinear} shows that the degradation tracks
\emph{memory load}, the number of overlapping associations stored, far more than
elapsed context.

Three 2026 papers attack this with explicit bounded memories beside the recurrent
state and a rule for what to write into them. HOLA~\cite{cui2026hola} keeps an
exact key-value cache and admits a token when the recurrent state's prediction
residual for it is large. Raven~\cite{afzal2026raven} keeps a fixed set of slots
and routes each token to a subset by a learned, input-dependent router.
Proteus~\cite{bayat2026proteus} activates memory capacity on a position schedule
so early tokens cannot pollute the whole memory. Each rule looks at the
\emph{input} (its novelty, its residual, its routing logits) or at
\emph{position}. None looks directly at the \emph{conflict} between the incoming
association and what is already stored. This paper tests whether that conflict
signal helps, under a controlled protocol fixed before the sweep, and finds that
it does not: on this task a learned writer whose gate sees nothing derived
from the stored keys or values matches or beats every other learned writer, and
a parameter-free rule beats them all.

\subsection{Research question and goals}

The research question is: \emph{at a fixed memory budget, does an explicit
per-slot interference estimate improve how a bounded memory is allocated,
measured as exact recall on associative recall tasks whose load exceeds the
budget?} The question is measurable (exact recall, paired against baselines on
identical test sequences), specific (one signal added to an otherwise shared
architecture), and relevant to a live gap in the literature
(Section~\ref{sec:related}).

The goal of the project is to answer it with a controlled architecture
comparison. The candidate solution is a small learned write controller that
receives, for every memory slot, the similarity of the incoming key to the slot's
key and the disagreement between the incoming value and the slot's value,
alongside input novelty and slot age. It outputs differentiable per-slot write
gates. Backbone, memory, and controller train jointly on query-answer
cross-entropy.

\subsection{Hypotheses}

\textbf{H1.} At matched total memory and training compute, the controller
improves exact recall by at least five percentage points over the strongest
validation-selected baseline on sequences with 64 to 128 distinct associations
at slot budgets of 32, 64, and 128. ``Matched training compute'' means
equal steps and batch size, not equal wall time; the strongest baseline is
whichever writer other than the controller scores highest on validation in that
cell, which in every cell is the pair-only recency rule added after the
proposal (Section~\ref{sec:changes}). Exact recall is defined in
Section~\ref{sec:protocol}.

\textbf{H2.} Removing the interference features while holding the controller's
size fixed reduces that gain, showing that the interference signal carries
information the input alone does not.

\subsection{Approach and contributions}

The applied ML problem is supervised sequence-to-token prediction on a
synthetic recall task. The method of analysis is a controlled architecture
comparison: seven writers (the controller, two ablations of it, one modeled
on Raven's router, and four rule-based writers, two modeled on HOLA and
Proteus) on one
backbone, one memory, one data distribution, and one training schedule, with
three seeds per cell, paired bootstrap intervals over shared test sequences,
and explicit state-byte accounting. Every batch of runs after the proposal's
pilot was pre-registered with a prediction in a lab notebook before launch, and every change to the
protocol after the proposal is listed in Section~\ref{sec:changes}.
Everything is implemented in PyTorch; 108 sweep runs plus 60 follow-up runs
completed without a failure on one GPU.

The contributions are the answers and the tools that produced them:
\begin{enumerate}
\item \textbf{A negative result on both hypotheses, with the mechanism.}
A learned controller with interference features loses to a parameter-free
pair-only rule in all six cells (Table~\ref{tab:final}), and an ablation whose
gate sees nothing derived from the stored keys or values beats the controller
at both $N = 64$ budgets. The gate statistics show why: the controller admits
69 to 82\% of pairs where the rule admits all of them, and no learned writer
ever overwrote an updated key in place.
\item \textbf{A capacity analysis for bounded-memory recall.} Closed forms
for three idealized policies give, per cell, what the pair-only rule answers
(40\% at 64 associations and 32 slots), what in-place update handling would
add (3.8 percentage points, pp), and what no policy can exceed (50\%). They
show that the proposal's target cell could not separate the hypotheses, in
which cells H1 was attainable at all, and they cost nothing to compute before
a sweep.
\item \textbf{The pair-only rule as the reference.} Admit every pair and
nothing else is a reference every cited allocation mechanism can be compared
against: it has no parameters, its recall is the closed form exactly, and
here it beats everything learned.
\item \textbf{A protocol lesson.} Hyperparameters selected on one seed, in a
capacity-bound cell, produced a false positive for H2 that only an
equal-learning-rate check exposed; the paper reports both comparisons and the
re-selection that confirmed the controller's setting.
\end{enumerate}

Section~\ref{sec:related} surveys allocation mechanisms, Section~\ref{sec:method}
gives the task, architecture, controller, and baselines,
Section~\ref{sec:results} the protocol, the sweep, the follow-up checks, and
the pilot that validated the pipeline, Section~\ref{sec:discussion} the
interpretation, including the online-caching view and the limitations, and
Section~\ref{sec:conclusion} what the study rules out and what it does not.

\section{Related Work}
\label{sec:related}

\subsection{Survey method}

Following the structure of the Preferred Reporting Items for Systematic
Reviews and Meta-Analyses (PRISMA 2009)~\cite{moher2009prisma} in a light form
suited to a course paper: a stated question, explicit eligibility criteria, documented
searches, and a flow count. The question was \emph{which mechanisms decide what
a bounded-memory sequence model writes, and has interference between stored
associations been used as a write signal?} Three arXiv searches on 2026-10-15,
the proposal's references, and eleven foundational papers identified 44
records, and citation chasing from the included papers on 2026-10-24 added
2 more; 33 were unique; 9 were screened out by title and abstract
(retrieval augmentation, agent memory, video, serving systems, surveys, a
chain-of-thought theory paper, a full-cache method, and one windowed-attention
paper whose abstract could not be verified); 24 were assessed and
included. Five online-caching papers, hand-added on 2026-10-27 when the
results called for that theory (Section~\ref{sec:caching-rw}), bring the
included set to 29. The full log with queries and per-record
exclusion reasons is in the project repository
(\texttt{paper/prisma/search-log.md}).

\subsection{Bounded-state backbones and their write rules}

Linear attention~\cite{katharopoulos2020linear} stores associations as a sum of
outer products $\sum_t v_t k_t^\top$; every token writes with equal weight.
Fast-weight programmers~\cite{schlag2021fastweight} introduced the delta rule,
which subtracts the state's current prediction before adding, so a write
\emph{corrects} rather than accumulates. Gated linear attention
(GLA)~\cite{yang2023gla} adds a data-dependent decay gate; DeltaNet~\cite{yang2024deltanet} and Gated
DeltaNet~\cite{yang2024gateddeltanet} make the delta rule and its decay trainable
at scale; Mamba~\cite{gu2023mamba} reaches a similar place through selective
state-space parameters. Based~\cite{arora2024based} combines a small
linear-attention state with sliding-window attention and shows the
recall-throughput trade-off directly. Attention with bounded-memory control
(ABC)~\cite{peng2021abc} frames linear
attention and several of its relatives as attention over a bounded memory of
fixed size, with a \emph{control} function that decides how each token is
organized into the memory, and replaces the heuristic control of earlier
variants with one learned from context. Gated Slot Attention~\cite{zhang2024gsa}
builds on ABC, and its successor GSA-2~\cite{li2026gsa2} organizes the state as
shared latent slots with decoupled erase and write gates on both the key and
value side.
Variational Linear Attention~\cite{pandey2026vla} casts each write as a
regularized least-squares step and bounds the state norm. In all of these the
write decision is a function of the token and a learned gate; the state is
addressed implicitly through key overlap, and the mechanistic study by Lee et
al.~\cite{lee2026howlinear} shows that recall degrades with the number of
overlapping writes.

\subsection{Allocation, routing, and eviction into explicit memory}

Neural Turing Machines~\cite{graves2014ntm} and the Differentiable Neural
Computer~\cite{graves2016dnc} are the classical learned-allocation designs: NTM
addresses by content and location, DNC adds a usage vector and allocates the
least-used slot. NTM's content addressing already computes, for every memory
row, the cosine similarity between the emitted key and that row, which is our
first interference feature; what neither model does is use that similarity,
or the disagreement between the incoming value and the stored one, to decide
\emph{whether and where to write}. Our age and usage features are DNC-style.
Titans~\cite{behrouz2024titans} gates memory
updates by \emph{surprise}, the gradient of a reconstruction loss, which is an
input-side novelty signal. HOLA~\cite{cui2026hola} (``a hippocampus for
linear attention'') keeps an exact key-value cache beside a linear-attention
state and admits a token when the state's delta-rule prediction residual for
it is large; the residual is a value-conflict measure, but one aggregated over
the whole state rather than evaluated per slot, and admission never looks at
what the cache holds. Our residual-cache writer keeps that admission rule on a
slot memory. Raven~\cite{afzal2026raven} keeps a fixed set of memory slots and
routes each token to a subset of them with a learned router conditioned on the
token; the router's input is the token's own representation, so routing is
input-dependent by design, and the paper reports recall gains over an unrouted
state at equal memory. Our novelty ablation is its single-slot analogue. ARM~\cite{zeng2026arm} does the same for a Transformer key-value (KV)
cache with a
Gumbel-softmax router and sigmoid-gated blends. IndexMem~\cite{yang2026indexmem}
trains an indexer to score KV entries for eviction. Fast-weight Product Key
Memory~\cite{zhao2026fwpkm} updates only activated slots of a large sparse
memory. RAM-Net~\cite{xiao2026ramnet} is the closest in motivation to this
paper: it names the mixing of unrelated tokens in a shared state as the cause
of poor fine-grained recall and answers it with an address decoder that maps
each key to a sparse set of slots, so tokens with disjoint addresses cannot
interfere. The address is a function of the key alone; the decoder never
inspects what a slot currently holds. Proteus~\cite{bayat2026proteus} sidesteps allocation by unlocking
memory capacity on a position schedule, so that early tokens cannot occupy
the whole memory and capacity grows as the sequence does; our position writer
keeps the schedule without the growth. Memory
Caching~\cite{behrouz2026memcache} sidesteps allocation by letting memory
grow. Zoology~\cite{arora2023zoology} and
RULER~\cite{hsieh2024ruler} supply the recall evaluations the field uses.

\subsection{Online caching}
\label{sec:caching-rw}

A bounded memory with an admission rule is an online cache, and that
literature supplies the bounds the discussion uses. Belady's
rule~\cite{belady1966study} is the offline optimum: evict the entry whose next
use is farthest away. Sleator and Tarjan~\cite{sleator1985amortized} showed
that no deterministic online eviction rule is better than a factor of the
cache size from it in the worst case and that LRU and FIFO meet that bound.
Learning enters when something observable predicts reuse: Lykouris and
Vassilvitskii~\cite{lykouris2018competitive} bound caching with a learned
next-use predictor by its error, Song et al.~\cite{song2020lrb} learn
Belady's decision from request-stream features, and
TinyLFU~\cite{einziger2017tinylfu} puts a frequency-based admission filter in
front of a conventional eviction rule, which is structurally what a learned
write gate on a slot memory is.

\subsection{The gap}

Every allocation rule above decides from the input (novelty, surprise, the
state's residual, a router's logits, a key's address) or from position
(schedule, recency), with memory-side statistics such as DNC's usage used only
to pick a free slot. ABC and RAM-Net come nearest, since both learn a per-token
slot assignment and RAM-Net states interference as its target, but each
decides from the token alone and avoids conflict by construction rather than
measuring it. None compares the incoming association with each slot's
\emph{value} as well as its key and uses that per-slot conflict as the write
signal. Lee et al.~\cite{lee2026howlinear} show for superposed linear states
that recall degrades with the number of overlapping associations; whether the
same holds for a slot memory, where one-hot writes never overlap but can
evict, is what the capacity analysis of Section~\ref{sec:protocol} makes
precise. The controller in Section~\ref{sec:controller} adds the per-slot
conflict signal and nothing else, so the comparison isolates its value.

\section{Methodology}
\label{sec:method}

\subsection{Task: multi-query associative recall with updates and distractors}
\label{sec:task}

Each sequence has three regions (Fig.~\ref{fig:block}). The \emph{context
block} holds $N$ queried pairs and $D$ distractor pairs, each a key token
followed by a value token, in random order. The \emph{update block} repeats $U$
of the queried keys with a new value; the correct answer for an updated key is
its latest value. The \emph{query region} presents each queried key once more;
the label at that position is the final value. Query positions follow Zoology's
power-law gap distribution, shifted by a minimum delay $\delta$ so delay is a
separate knob (the generator applies $2\lfloor\delta/2\rfloor$ so that queries
stay on even positions). The vocabulary of $V$ tokens is split into $V/2 - 1$
key tokens and $V/2$ value tokens. Every position that is not part of a pair or
a query holds a \emph{filler} token drawn uniformly from the whole vocabulary,
so a filler token can coincide with a queried key; at the sweep's sizes this
happens before the key's query for 0.95\% (N = 64) and 1.85\% (N = 128) of
queries. Loss and metrics use only the $N$ answer positions per sequence; the
answer token never appears in the input. The generator is adapted from
Zoology's \texttt{multiquery\_ar} and \texttt{forgetting\_mqar} (Apache-2.0)
with the distractor and delay extensions added.

Sweep setting: $V = 8192$; $N = 64$ with $U = D = 16$ at sequence length 512,
and $N = 128$ with $U = D = 32$ at length 1024 (its context block plus queries
do not fit in 512); $\delta = 0$ except in the delay sweep of
Section~\ref{sec:final-results}. Splits: 100{,}000 training, 5{,}000
validation, and 10{,}000 test sequences from distinct seeds, with exact
duplicates removed from validation and test; checkpoint selection scores the
first 1{,}280 validation sequences. The pilot of Section~\ref{sec:pilot} used
$V = 2048$, length 128, $N = 16$, $U = D = 4$, $S = 16$.

\subsection{Architecture}
\label{sec:arch}

\subsubsection{Backbone}
$L$ pre-norm blocks of gated linear attention (GLA)~\cite{yang2023gla}, each
followed by a multilayer perceptron (MLP), using the
\texttt{flash-linear-attention} implementation. Per head and layer GLA keeps a
$d_k \times d_v$ recurrent state $\mathbf{S}_t$ updated with a learned,
data-dependent decay $\alpha_t \in (0,1)^{d_k}$:
\begin{equation}
\mathbf{S}_t = \mathrm{diag}(\alpha_t)\,\mathbf{S}_{t-1} + \tilde{k}_t^{\top} \tilde{v}_t,
\qquad o_t = \tilde{q}_t \mathbf{S}_t,
\label{eq:gla}
\end{equation}
where $\tilde{q}_t, \tilde{k}_t \in \mathbb{R}^{d_k}$ and $\tilde{v}_t \in
\mathbb{R}^{d_v}$ are the layer's own projections of its input and $\alpha_t$
is a low-rank sigmoid gate of the input; the output passes through a gated
RMS normalization as in the reference implementation. With
$d_{\text{model}} = 256$ and 4 heads, $d_k = 32$ and $d_v = 64$, so the state
is $2 \times 4 \times 32 \times 64$ fp32 values, 64~KB per sequence. Both the
pilot and the sweep use $L = 2$; the sweep's vocabulary is 8192 (5.99M
parameters in total) against the pilot's 2048 (2.84M). The proposal's
20M-parameter scale was not reached (Section~\ref{sec:changes}).

\subsubsection{Projections}
From the backbone output $h_t \in \mathbb{R}^{d_{\text{model}}}$: $q_t = W_q
h_t$, $v_t = W_v h_t$, and $k_t = W_k h_{t-1}$, all in $\mathbb{R}^{d}$ with $d
= 128$. The key is projected from the \emph{preceding} position because an
association is a (key, value) token pair: the value token's own representation
carries the value, and the token before it carries the key. Without this
one-step shift the backbone must first learn to copy each key one position
forward before the memory can store anything retrievable; in a pilot diagnostic
that cost a four-fold difference in recall at equal training steps
(Section~\ref{sec:pilot}). All writers share this projection, so it does not
favor the controller.

\subsubsection{Slot memory}
$S$ slots, each a key $k_j$ and value $v_j$ in $\mathbb{R}^{d}$, plus scalar
age $a_j$, usage $n_j$, and occupancy $f_j \in [0, 1]$, all initialized to
zero. Read is attention over occupied slots:
\begin{equation}
\begin{split}
\alpha_{t,j} &= \softmax_j\!\left(\frac{q_t^\top k_j}{\sqrt{d}} + \log \max(f_j, 10^{-6})\right),\\
r_t &= \sum_j \alpha_{t,j} v_j ,
\end{split}
\label{eq:read}
\end{equation}
so an empty slot is down-weighted by a factor of $10^{-6}$ rather than removed,
and an empty memory reads a uniform average of zero vectors.
Write is a convex update of every slot, as in the proposal:
\begin{equation}
m_{t,j} = (1 - g_{t,j})\, m_{t-1,j} + g_{t,j}\, u_t,
\label{eq:write}
\end{equation}
where $m_j = (k_j, v_j)$ is the slot's contents and $u_t = (k_t, v_t)$ the
incoming association,
with $a_j \leftarrow (a_j + 1)(1 - g_{t,j})$, $n_j \leftarrow n_j + g_{t,j}$,
and $f_j \leftarrow (1 - g_{t,j}) f_j + g_{t,j}$. All three projections are
affine, $h_0 = 0$, and the memory tensors are kept in fp32. At each position the memory is
read \emph{before} it is written, so a query token sees what was stored before
it.

\subsubsection{Answer head and loss}
A two-layer MLP on $[h_t ; r_t]$ produces logits $\ell^{\text{out}}_t$ over the
vocabulary. The loss is the mean cross-entropy over the answer positions of a
batch,
\begin{equation}
\mathcal{L} = -\frac{1}{|A|}\sum_{(b,t) \in A} \log \softmax\big(\ell^{\text{out}}_{b,t}\big)_{y_{b,t}},
\label{eq:loss}
\end{equation}
where $A$ is the set of (sequence, position) pairs with a label $y_{b,t}$ and
$|A| = BN$ for a batch of $B$ sequences.

\subsection{The interference-aware controller}
\label{sec:controller}

For each slot $j$ the controller builds a six-dimensional feature vector
\begin{equation}
\begin{split}
\phi_{t,j} = \Big[\,
&\underbrace{s_{t,j},\; \delta_{t,j}}_{\text{interference}},\;
\underbrace{1 - \max_{j'} s_{t,j'}}_{\text{novelty}},\;
\tfrac{a_j}{T},\; \tfrac{n_j}{T},\; f_j \,\Big],\\
s_{t,j} &= \frac{f_j\, k_t^\top k_j}{\sqrt{\lVert k_t\rVert^2 + \epsilon}\,\sqrt{\lVert k_j\rVert^2 + \epsilon}},\\
\delta_{t,j} &= \frac{\sqrt{\lVert v_t - v_j\rVert^2 + \epsilon}}{\sqrt{d}},
\end{split}
\label{eq:features}
\end{equation}
where $T$ is the sequence length, $s_{t,j}$ is the cosine similarity of the
incoming key to the slot's key weighted by the slot's occupancy, and
$\epsilon = 10^{-2}$ keeps the gradient of the normalizations bounded when a
slot key is near zero (the gradient of $1/\lVert x\rVert$ is unbounded at the
origin, and empty slots start there; a pilot diagnostic traced a loss
divergence to this). The first feature is high when the incoming
key would land on a slot that already holds a similar key, which is the
condition under which a write \emph{overwrites} rather than \emph{adds}. The
second says whether that overwrite would change the stored answer. Together they
distinguish a harmless duplicate (similar key, same value) from a genuine key
update (similar key, new value) and from a collision between unrelated
associations whose keys happen to be close.

A two-layer MLP (the \emph{slot MLP}, hidden width $H_s$) maps the six
features $\phi_{t,j}$ to a logit $\ell_{t,j}$ that decides \emph{where} a write
goes. A second two-layer MLP (the \emph{write MLP}, hidden width 64, fixed)
decides \emph{whether} to write at all, producing a scalar logit $w_t$ from a
pooled memory summary, the novelty, the mean occupancy $\frac{1}{S}\sum_j f_j$
and the mean value disagreement $\frac{1}{S}\sum_j \delta_{t,j}$, concatenated
with $z_t = W_z h_t + b_z \in \mathbb{R}^{16}$, a low-dimensional projection of
the current token's representation. The content input is what lets the
controller learn that a value token following a key is worth storing and a
filler token is not; without it the decision to write can depend only on memory
statistics, and in the pilot diagnostics the controller then learned on some
seeds and not others (Section~\ref{sec:pilot}). A learnable scalar prior
$\lambda$ (initialized to 5) adds $\lambda\,(a_j/T + 1 - f_j)$ to $\ell_{t,j}$,
so at initialization the slot choice prefers empty and then oldest slots, which
is the recency writer's rule; the slot MLP only has to learn deviations from
it. The write MLP's output bias is initialized to zero, so $\sigma(w_t) = 0.5$
at initialization and the controller starts as a soft recency writer with
half-strength writes. The gate is
\begin{equation}
\begin{split}
g_{t,j} &= \sigma(w_t)\, \hat{p}_{t,j},\\
\hat{p}_{t} &= \onehot\!\big(\argmax_j \ell_{t,j}\big) + \softmax_j(\ell_{t,\cdot})\\
&\quad - \mathrm{sg}\big[\softmax_j(\ell_{t,\cdot})\big],
\end{split}
\label{eq:gate}
\end{equation}
where $\sigma$ is the logistic function and $\mathrm{sg}$ stops gradients: the
forward pass writes exactly one slot (a straight-through estimator) and the
backward pass uses the gradient of the softmax in its place. The write can
still be suppressed entirely through $\sigma(w_t)$. A fully soft gate was
tried first and did not learn: at initialization it spreads each association
across all slots, the memory never holds a retrievable entry, and so no
gradient arrives to sharpen it. Hard forward selection with a soft backward
path is the same device ARM uses for its slot router~\cite{zeng2026arm}. In
the sweep ($H_s = 32$, chosen on validation, Section~\ref{sec:protocol}) the
gate networks have 1{,}603 parameters including $\lambda$, and the content
projection 4{,}112; the pilot used $H_s = 64$ (1{,}859). The controller's
decision depends only on the current association and the memory, so it adds no
per-sequence state beyond the memory's own age, usage, and occupancy scalars,
which are counted in the budget.

\textbf{H2 ablations.} Setting \texttt{interference=False} zeroes the two
per-slot interference features $s_{t,j}$ and $\delta_{t,j}$ and the pooled mean
disagreement, and leaves everything else identical, including parameter count.
It keeps the novelty feature, which is itself derived from the stored keys, so
this \emph{novelty ablation} is a router that sees whether the incoming key is
already in memory but not where or with what value. It was designed as the
simplified form of Raven's routing signal and pre-registered as the H2
ablation; a code audit after the sweep found it had been labelled
``input-only'', which it is not. A second ablation, \texttt{novelty=False} as
well, is the \emph{input-only ablation}: its gate sees the content projection
$z_t$ and the slots' age, usage and occupancy, nothing derived from stored keys
or values. H2 as stated is the comparison against the input-only ablation; the
novelty ablation separates the per-slot detail from the global signal, and the
two readings give the same sign in every cell where both were run
(Section~\ref{sec:final-results}).

\subsection{Baselines}
\label{sec:baselines}

All writers share the backbone, projections, memory, and answer head; only the
gate rule differs (Table~\ref{tab:baselines}). The three writers modeled on
cited mechanisms are deliberate simplifications, re-implemented from the
papers' descriptions because none had public code at the time of writing, and
each drops something: the residual cache keeps HOLA's residual-threshold

model; the novelty ablation keeps Raven's input-dependent routing but not its

schedule but not the capacity growth that is its point. The pair-only recency
rule uses one fact about the task, which positions hold pairs, so it is a
reference policy rather than a deployable writer.

\subsection{Training, accounting, and implementation}
\label{sec:training}

Every sweep run uses the same recipe: AdamW ($\beta_1, \beta_2 = 0.9, 0.95$;
weight decay 0.1 on every tensor with two or more dimensions, including the
embedding), 8{,}000 steps of batch 64 sampled with replacement from the
100{,}000 training sequences, 200 warmup steps then cosine decay to zero,
gradient clipping at 1.0, validation every 500 steps on the first 1{,}280
validation sequences, and the best-validation checkpoint for test evaluation
(Section~\ref{sec:protocol}). The forward pass runs under bf16 autocast,
including the memory read, the similarity features and the gate MLPs; the
memory tensors and the convex update of Eq.~\eqref{eq:write} are fp32. The
learning rate is selected per writer and the controller's slot-MLP width
$H_s$ on validation (Section~\ref{sec:protocol}); the selected values are
$3 \times 10^{-4}$ and $H_s = 32$ for the controller and the input-only
ablation, $10^{-3}$ for the novelty ablation, $6 \times 10^{-4}$ for the
residual cache, and $3 \times 10^{-4}$ for the rule-based writers. The pilot
used $3 \times 10^{-4}$, $H_s = 64$, batch 64, 200 warmup steps, and 4{,}000
steps. State bytes per sequence are reported as the backbone's recurrent state
plus $S(2d + 3)$ fp32 values of memory plus any writer statistics (zero for
every writer; the residual cache reports 4~B as an accounting artefact of its
scalar parameters); at $S = 64$ that is 64~KB backbone and 65~KB memory,
129~KB in all. The per-timestep memory update is compiled and the whole
training step captured as a CUDA graph; the compiled path is tested to be
numerically identical to the eager loop for every writer and is 3.4 times
faster.

The model, data generator, training loop, metrics, and experiment scripts are
written in PyTorch and live in the project repository (\url{REPO-URL}; a
snapshot accompanies the submission) with unit tests (\texttt{pytest}: data
splits, the memory update, the gates, the ablations' feature sets, the
compiled path, gradient flow, the attention reference). One command runs one
(writer, seed, configuration) cell and writes a results file with the
effective configuration and the commit hash; the analysis scripts regenerate
every table and figure below from those files. The lab notebook
(\texttt{experiments/LOG.md}) holds the pre-registered entry for every batch of
runs. A companion notebook (\texttt{Ellis-RP3.ipynb}) regenerates the tables and
figures from the shipped run files and runs the tests.

\subsection{Experimental protocol}
\label{sec:protocol}

\textit{Factors.} Memory budget $S \in \{32, 64, 128\}$; associations $N \in
\{64, 128\}$; writer $\in$ \{controller, novelty ablation, recency, pair-only
recency, residual cache, position activation\} in the sweep, plus the input-only
ablation and a full-attention reference (causal softmax attention with rotary
positions in place of GLA, no slot memory, so an unbounded key-value cache)
in the follow-up runs. Updates and distractors fixed at $N/4$ each; minimum
query delay $\delta = 0$, with a delay sweep $\delta \in \{64, 128, 192\}$ at
$N = 64$, $S = 64$. The $N = 64$ column trains at length 512 and tests at 512,
1024, and 2048; the $N = 128$ column trains at length 1024 and tests at 1024,
2048, and 4096. Test sequences are freshly generated.

\textit{Capacity analysis.} Three idealized write policies bound what a
writer can do in a cell, and all three have closed forms
(Table~\ref{tab:ceiling}; the generator-replay simulation in
\texttt{experiments/analysis/ceiling.py} agrees with them within 0.5~pp). Let
$P = N + D$ be the context pairs and $Q = N - U$ the queried keys whose context
value is final. A policy that admits every pair at its value position, writes
an update to a fresh slot, and evicts the oldest slot holds the last $S$ pair
writes, so it answers $U + \min(S - U, P)\,Q/P$ of the $N$ queries; this is
the pair-only recency writer, and its measured recall matches the formula to
0.1~pp in every cell. The same policy with updates overwritten in place holds
$U + \min(S - U, Q + D)\,Q/(Q + D)$, the best a rule can do without knowing
which pairs will be queried. A policy with that foreknowledge, which also
rejects distractors, answers $\min(S, N)/N$, the bound for any writer. At
$N = 64$, $S = 32$ these are 40.0, 43.8, and 50\%; at $S = 64$, 70.0, 81.3,
and 100; at $S = 128$ all 100. H1 asks for $+5$~pp over the pair-only rule, so
it is attainable only where the foreknowledge bound exceeds the rule by at
least 5~pp: at $N = 64$ in the 32- and 64-slot cells, and at $N = 128$ in the
64- and 128-slot cells. The other two cells (the rule at 100\% at $N = 64$,
$S = 128$; at the bound at $N = 128$, $S = 32$) are reported but cannot
support H1 by construction. Of the margin a learned policy could win over the
rule, the part that needs no foreknowledge is the in-place handling of updates
(3.8~pp where the rule holds half the context, 11.3~pp where it holds most of
it), which is the behaviour the interference features were designed for;
Section~\ref{sec:final-results} measures whether any writer learned it. The
proposal named $N = 64$, $S = 32$ as its target; the rule's 40\% there leaves
10~pp to win, less than the learned writers' seed spread, so the hypotheses
are decided in the 64-slot cell at $N = 64$ and the 64- and 128-slot cells at
$N = 128$.

\textit{Checkpoint selection.} Each run is evaluated at the checkpoint with the
best validation recall during training (the first 1{,}280 validation sequences,
scored every 500 steps), not at the last step. On this task the cosine tail can
move a run from the pair-only write policy into a worse one
(Section~\ref{sec:changes}); best-validation selection reports the policy a
run reached, and is how the reference MQAR work reports
accuracy~\cite{arora2023zoology}.

\textit{Metric, seeds, and decision rules.} Exact recall of a sequence is the
fraction of its $N$ answer positions whose argmax prediction equals the label;
a run's recall is the mean over the 10{,}000 test sequences. Three seeds per
cell; a cell reports the mean and the sample standard deviation over seeds.
Hypotheses are tested on differences: for a pair of writers in a cell, the
per-sequence recall difference is formed on the shared test set for each seed
and three statistics are reported. (i) The mean difference in percentage
points (pp) with a 95\% paired bootstrap interval (2{,}000 resamples)
over test sequences pooled across seeds~\cite{efron1979bootstrap}; this
interval is within $\pm 0.3$~pp in every cell and reflects test-sequence
sampling only. (ii) The three per-seed differences. (iii) A 95\% $t$-interval
for the mean of the per-seed differences (two degrees of freedom, so
$\pm 4.30$ standard errors), which is the statistic the verdicts use, because
with three seeds no sign pattern reaches $p < 0.05$ on its own (three agreeing
signs give $p = 0.125$ one-sided). Rules, fixed before the results were
tabulated: H1 is \emph{supported} in a cell if the seed interval of
controller minus the strongest other writer lies entirely above $+5$~pp,
\emph{reversed} if it lies entirely below 0, and \emph{not supported}
otherwise. H2 uses the controller minus the input-only ablation at the same
learning rate: \emph{supported} if the interval lies above 0, \emph{reversed}
if below 0, \emph{not supported} otherwise. Secondary metrics: state bytes,
throughput, and the write-gate statistics (write fraction, fraction of each
token class written, slot entropy, in-place update rate) that show \emph{how}
each writer uses its budget.

\textit{Selection.} The learning rate for each writer and the controller's
slot-MLP width are chosen on validation recall at $N = 64$, $S = 32$ on one
seed and then frozen (Table~\ref{tab:hparams}); the controller's choice was
re-selected on three seeds at $N = 64$, $S = 64$ after the sweep
(Section~\ref{sec:final-results}).

strongest other writer in every cell is pair-only recency. At $N = 64$ it leads
the controller by 6.6~pp at $S = 64$ (seed interval $[-8.5, -4.6]$: reversed),
by 17~pp in the 32-slot cell ($[-33.8, -0.6]$: reversed), and by 33~pp at

seed at 48\% ($[-74, +8]$: not supported, every seed negative). At $N = 128$

statistics (Figs.~\ref{fig:sweep}c and~\ref{fig:sweep128}c) give the
mechanism: the controller admits 69\% of pairs at $N = 64$, $S = 64$ and 82\%
at $S = 128$ while still writing some filler, whereas the rule admits every
pair and nothing else. In the 64-slot cell a writer that admitted every pair
and overwrote updates in place would reach 81\%, and one that also rejected
distractors 100\% (Table~\ref{tab:ceiling}); the controller's shortfall is an
under-admission failure, not a capacity one. Against the three baselines the
proposal named (recency, residual cache, position activation), which are at or
near chance in every cell above $S = 32$ except naive recency at $N = 64$,

finding in its own right, but it is not H1: H1 names the strongest other
writer, and that writer is the pair-only reference added after the proposal,
which no writer without the generator's layout could implement exactly. The
task itself is solvable: the full-attention reference reaches
ATTN-RESULT at the training length with a 2.1~MB key-value cache against the
bounded writers' 129~KB of state.

\textit{H2 test.} H2 is not supported at either $N = 64$ budget and reversed
at $S = 64$. The decisive comparison is the input-only ablation, whose gate
sees nothing derived from the stored keys or values, trained at the
controller's learning rate: it scores 66.0\% at $S = 64$ (seeds 65.8 to 66.1)
and 94.0\% at $S = 128$ (93.0 to 95.6). Controller minus input-only is
$-2.5$~pp at $S = 64$ (seed interval $[-4.1, -0.9]$: reversed) and $-27$~pp at
$S = 128$ (every seed negative, $[-68, +13]$: not supported, because one
controller seed's 48\% widens the interval). The input-only ablation matches
the novelty ablation within 0.2~pp at $S = 64$ and 2.0~pp at $S = 128$ (the
novelty ablation is ahead there on every seed), and has the tightest seed
spread of any learned writer. Its admission statistics show what it learned:
71 to 91\% of pairs and under 5\% of filler at $S = 64$, i.e.\ ``this token is
a pair's value position'', read off the backbone's content projection. Adding
key novelty on top of that moves recall by at most 2~pp; adding the per-slot
key similarity and value disagreement makes the gate admit fewer pairs and vary
more across seeds. The literal reading of H2, controller minus novelty
ablation at equal rate, has the same sign: $-2.3$~pp at $S = 64$ and $-29$~pp at
$S = 128$. The best-of-each comparison in the upper rows of
Table~\ref{tab:final}, which had the controller 17.9~pp ahead of the novelty
ablation at $S = 64$, is a learning-rate artefact: the ablation's selected rate,
$10^{-3}$, came from a single seed at $S = 32$, and at that rate every learned
writer writes every pair plus 18 to 23\% of filler. In the capacity-bound

controller on every seed ($[-12, +2]$: not supported). At $N = 128$,
N128-INPUT-ONLY-RESULT. The interference signal carries no information a
learned admission gate used on this task: a gate that ignores the stored
content is within 2~pp of the best learned writer at both $N = 64$ budgets and

\textit{How each writer spends its budget.} Fig.~\ref{fig:sweep}(c), at the

residual cache's threshold separates pairs from filler only at $S = 32$ (69\%

collapses onto a subset of slots; the differences are in \emph{what} is
admitted, not \emph{where}. The one thing stored content could have bought

learned: replaying the hard writes of every learned writer at $N = 64$, both

fraction of updates written into the slot that still held the key is 0.00 for
the controller on every seed, 0.00 to 0.01 for the ablations, and 0.02 for the
pair-only rule by chance, although the key was still held at two thirds of the
updates at $S = 64$ and nearly all at $S = 128$. The interference features
produced the behaviour they were designed for 0\% of the time.

\textit{Cost.} Every writer has 5.99M parameters; the learned writers add
5{,}715 to the rule-based ones (1{,}603 in the gate networks and 4{,}112 in the
content projection), the residual cache 2. State per sequence at $S = 64$ is
129~KB (64~KB backbone, 65~KB memory). On the compiled fast path at length 512
a run takes 13 to 19 minutes for the rule-based writers (230k to 330k tokens
per second) and 23 to 29 for the learned ones (150k to 190k), two sharing an
RTX 5090 at 12 to 16~GB each; at length 1024, 27 to 62 minutes, one at a time
at 18 to 30~GB. Test evaluation on 10{,}000 sequences takes 3 to 10~s at
length 512, 10 to 31~s at 1024, and up to 7.7 minutes at 4096. Training plus
test time sums to 56 GPU-hours for the 108 sweep runs, 15 for the 36 follow-up
runs at the target, and 7 for the 24 skew-pilot runs.

\subsection{Pilot: pipeline validation}
\label{sec:pilot}

A single-seed pilot at vocabulary 2048, length 128, $N = 16$, $U = D = 4$,
$S = 16$ (24 pair writes, 20 distinct keys) validated the pipeline and fixed
five things before any writer comparison, each found by a one-variable
diagnostic logged in the lab notebook: the one-step key shift of
Section~\ref{sec:arch} (the recency writer went from 12\% to 47\% on an
8-pair task at equal steps), the straight-through slot gate of
Section~\ref{sec:controller} (11\% to 81\% on the same task), the content
projection $z_t$ (a 16-pair task from 3\% to 92\% at 1{,}400 steps), the
recency prior $\lambda$ (from chance to 25\% by step 1{,}000 at 24 pairs), and
the $\epsilon$ in the similarity and distance features (gradient spikes of
$10^4$ to $10^5$ in the writer and projections, traced to the $1/\lVert
x\rVert$ factor, fell to 50). Unit tests cover split disjointness,
answer-position masking, the write's identity at zero gate, gate range, the
ablations' feature sets, the compiled path's equality with the eager loop,
and gradient flow into the writer and both memory projections; a 64-sequence
overfit check drives the loss under 0.1 in 300 steps. At the pilot scale the
controller led the novelty ablation by 1.3~pp on one seed (51.9 against
50.7\% at length 128, paired interval $[+1.0, +1.5]$), a margin the three-seed
sweep did not reproduce (Table~\ref{tab:final}). One pilot-scale run took 16
minutes on the eager loop at under 1~GB. The same setting, with three seeds
and 12{,}000 steps, is the skewed-key experiment of
Section~\ref{sec:discussion}.

\section{Discussion}
\label{sec:discussion}

\subsection{What the sweep shows}

Four things, each on three seeds per cell and paired on the same test
sequences.

\textit{The 32-slot cell cannot decide the hypotheses.} At 64 associations
with 16 updates and 16 distractors there are 96 pairs for 32 slots. The
pair-only rule holds the last 32 pair writes and answers 40\% of queries by
the closed form of Table~\ref{tab:ceiling}; overwriting updates in place would
add 3.8~pp, and foreknowledge of the queried keys 10~pp in all. That 10~pp is
the whole margin allocation could win there, and it is narrower than the
controller's seed range in the cell (19 to 31\%). The proposal named this cell
as the target. The capacity analysis was done after the first three-seed
results there and moved the decisive cells; done before the first target run
it would have moved the target.

\textit{A parameter-free rule beats every learned writer.} Pair-only recency
has no parameters in the writer and uses one fact about the task, which
positions hold pairs. It leads in all six cells, by 6.6~pp over the controller
at 64 associations and 64 slots and by 33~pp at 128 slots, where it is perfect,
and at 128 associations the margins are 16 to 30~pp (Table~\ref{tab:final}). The admission
statistics (Figs.~\ref{fig:sweep}c and~\ref{fig:sweep128}c) locate the loss:
the controller admits 69\% of pairs at 64 slots and 82\% at 128, and the rule
admits all of them. A writer that admitted every pair and rejected every
distractor could reach 100\% at 64 slots; no learned writer approached that,
and at $N = 64$ the best learned writer trails the rule by 4~pp in both
cells above 32 slots (the input-only ablation at 66.0\% at 64 slots; the
novelty ablation at 96.0\% at 128); at $N = 128$ the gap is 8~pp at both. Against the proposal's own baselines the picture reverses: the
residual cache and position activation are at or near chance above 32 slots,
naive recency reaches 29\% only at 128 slots, and the controller beats the
best of the three by 20 to 63~pp in every such cell. H1 nevertheless fails as defined, because it is stated against the
strongest other writer and that writer is the reference the proposal lacked; the margin over the proposal's own baselines is reported
as a separate result.

\textit{The interference signal carries nothing usable.} The decisive
comparison is the input-only ablation, whose gate sees the content projection
of the current token and the slots' age, usage, and occupancy, and nothing
derived from stored keys or values. At the controller's learning rate it beats
the controller by 2.5~pp at 64 slots and 27~pp at 128, every seed positive,
and matches the novelty ablation within 2~pp. Adding key novelty moves recall
by at most 2~pp; adding per-slot similarity and value disagreement makes the gate
admit fewer pairs and vary more across seeds (one of three controller seeds at
128 slots reached 48\% against 75 and 78). The gate that works learns one
thing, ``this token is the value position of a pair'', and reads it off the
backbone's representation of the token. The best-of-each comparison, which
had the controller 17.9~pp ahead of the novelty ablation at 64 slots, was a
learning-rate artefact of one-seed selection at the capacity-bound cell, and
the three-seed re-selection of the controller at the decisive cell returned
the sweep's own setting (63.5\% against 40 to 44\% for every other), so the
controller's loss is not a tuning accident.

\textit{Length does not matter; load does.} Every writer with a
position-independent policy is flat from the training length to four times
it, the fixed rules to within 0.1~pp and the learned ablations and the
residual cache to within 2~pp, because the task's context block is fixed and longer
sequences add only filler. The two writers that degrade with length, the
controller and naive recency, are the two whose admission drifts with
position; writing filler alone does not do it, since the novelty ablation at
its selected rate writes 18 to 20\% filler and is flat. This is the
memory-load account of Lee et al.~\cite{lee2026howlinear} seen from the
memory side: adding tokens that are not associations adds no load, and recall
does not move. The flat curves also mean this protocol is a weak test of
extrapolation; the delay sweep of Section~\ref{sec:final-results} is the test
that is not flat by construction. DELAY-DISCUSSION

\subsection{The writer as an online cache}

\textit{The writer is an online cache.} The slot memory is a cache of $S$
entries; each incoming pair is an insertion request that must be accepted or
dropped before the next token arrives, with no look-ahead. In that vocabulary
pair-only recency is first-in-first-out (FIFO) eviction behind a perfect
admission filter, the
capacity ceiling of Section~\ref{sec:protocol} is Belady's offline
optimum~\cite{belady1966study}, and H1 asks whether a learned admission policy
can beat FIFO online. Sleator and Tarjan~\cite{sleator1985amortized} showed
that no deterministic online eviction rule is better than a factor of $S$
from the offline optimum in the worst case, and that least-recently-used
(LRU) and FIFO eviction meet that
bound; the sharper point for this task is that when future requests are
independent of the past, an online policy has nothing to condition on, and
the only margin left is admission: rejecting tokens that will never be
queried. In MQAR as generated here every queried key is drawn uniformly from
the key vocabulary and every distractor key from the same pool, so at write
time a distractor is indistinguishable from a pair that will be queried, and
an update is recognizable only by its key already being stored. The
parameter-free rule therefore sits at the online optimum up to update
handling, and the sweep measures how close a learned gate gets to it: the
novelty and input-only ablations at the controller's learning rate come within
4 to 6~pp at both budgets, and the interference features move the gate away
from it. Seen
this way the negative result is the expected one, and the study's
contribution is the measurement of the gap and of its cause, under-admission
of pairs, rather than the direction of the sign.

\textit{Where a learned writer could win.} The same theory says when
learning should pay: when something observable at write time predicts reuse.
The learned-caching literature is built on exactly that condition. Lykouris
and Vassilvitskii~\cite{lykouris2018competitive} give an eviction rule whose
competitive ratio falls with the error of a next-use predictor and never
exceeds the no-advice bound; Song et al.~\cite{song2020lrb} train a predictor
of Belady's decision from features of the request stream; and TinyLFU
\cite{einziger2017tinylfu} is a frequency-based admission filter in front of
a conventional eviction rule, which is structurally what our controller is.
All three assume a skewed, temporally correlated request stream. We tested
this condition directly at the pilot scale (24 associations, 16 slots, length
128, three seeds; Table~\ref{tab:skew}): queried keys drawn from a Zipf distribution with exponent 2
over the key vocabulary and distractor keys from its cold remainder, so that
the key embedding alone predicts whether a pair will be queried; the controller and
pair-only recency trained for 12{,}000 steps at both distributions, and the
novelty ablation at the skewed one.
The prediction from the caching view held on the admission side and failed on
recall. With the reuse signal the controller learned to reject distractors on
two of three seeds (distractor admission 0.50 and 0.24 against pair admission
0.91 and 0.90; the third seed never left write-everything), the novelty
ablation on one of three, and at the uniform distribution all three controller
seeds converged toward admitting every token, which is FIFO. But pair-only
recency gains from the skewed distribution too, 79.6\% against 76.4\% at the
uniform one on the same schedule (three seeds within 1~pp in each), because
the skew makes the read easier for every writer. Against that matched control
the controller trails by 7.6~pp at the uniform distribution and by 1.1~pp on
its two good seeds at the skewed one (78.5 against 79.6), with the third seed
17~pp behind. The learned rejection therefore closes most of the gap to the
non-learned rule where it is learned, and does not cross it. At this scale the
learned rejection buys nothing: FIFO loses about 2.4 of 16 slots to
distractors, and the controller gives up 10\% of pairs to reject half of them.
Two further points carry back to the sweep. The controller gained 18~pp from
4{,}000 to 12{,}000 steps at the pilot scale, so the 8{,}000-step schedule of
Table~\ref{tab:final} may under-train the learned writers, and the
basin-dependence seen there recurs here (one seed in three). A writer that
could turn the reuse signal into a recall gain would need to reject
distractors without under-admitting pairs, and the budget where that trade
pays is one where distractors cost more than a sixth of the slots.

\subsection{Comparison with the cited mechanisms}

Of the three mechanisms the baselines model, the input-dependent router
(Raven~\cite{afzal2026raven}, our novelty and input-only ablations) is the
strongest: at the controller's learning rate it reaches 66\% at 64 slots and
94 to 96\% at 128, within 4 to 6~pp of the reference. The residual-gated admission
of HOLA~\cite{cui2026hola} learned a useful threshold only at 32 slots, where
it averaged 30\% with every seed above chance, 7~pp above the controller; above that its
learning rate, selected at 32 slots, left it admitting a quarter to a third of
every token class and at chance. That is an under-tuned baseline, not a
refutation of HOLA, whose cache is exact and whose residual comes from a full
language model. Position scheduling (Proteus~\cite{bayat2026proteus}) has no
admission rule and writes at every position, so at this density it is a
recency variant and stays at zero; its contribution in the original is
capacity growth, which this protocol does not test. The gain the capacity
analyses predicted for an interference signal at high load, where the
proposal expected the controller to pull away, does not appear: at 128
associations the controller's deficit to the reference is 16 to 30~pp, and at
no budget or load does it come within 6~pp.

\subsection{Strengths and limitations}

\textit{Strengths.} The comparison is controlled: every writer shares the
backbone, projections, memory, answer head, data, schedule, and state budget,
and the two ablations change input features without changing a single
parameter. Test sequences at the training length are identical across
writers for a seed, so every number in Table~\ref{tab:final} is exactly
paired. Each batch of runs after the pilot was pre-registered with a prediction,
and the predictions that failed (the controller's hidden size, the equal-learning-rate
check, the skewed-key pilot) are reported as failures. The two checks that
changed the paper's claims, the equal-rate comparison and the input-only
ablation, were run because a stated concern and a code audit called for them,
and both are in the record.

\textit{Limitations.} Hyperparameters were selected on one seed per grid
point (Table~\ref{tab:hparams}), and the sweep shows the cost: the hidden size
chosen for the controller gave 32.5\% on its grid seed and 19, 19 and 31\% on
the three sweep seeds at the same setting, and the residual cache's learning rate,
chosen at $S = 32$ where it then learned on all three seeds, leaves it at
chance at 64 and 128 slots. The sweep's best-of-each H2 comparison would have
supported H2 at $S = 64$; only the equal-learning-rate check showed the gap
was the ablation's one-seed rate selection, and only a code audit showed that
the pre-registered ablation still saw key novelty, which is why the input-only
ablation was added after the sweep. The selection recipe, not the
sweep, is what one seed per grid point weakens. The learned writers
are bimodal across seeds (one of three controller seeds at $S = 128$ reached
48\% against 75 and 78), so the three-seed means carry a spread the pooled
bootstrap interval does not show, and training is not bitwise reproducible at
a fixed seed on this hardware (Section~\ref{sec:final-results}), so the seed
is not a full description of a run. The three-seed re-selection at the
decisive cell (Section~\ref{sec:final-results}) returned the sweep's own
setting, so the H1 result there holds under proper selection, not only under
the original one-seed choice; but with three seeds the seed-level intervals
are wide, and several cells are ``not supported'' rather than ``reversed''
for that reason alone. The 8000-step schedule, fixed before the sweep, may
under-train the learned writers: several controller runs at $S = 64$ and
$S = 128$ were still rising at the last evaluation, and in the skewed-key pilot
(Section~\ref{sec:discussion}) the controller's gate learned to separate hot
from cold keys only at 12{,}000 steps, three times the pilot's own schedule
and 1.5 times the sweep's. Any follow-up should match a longer schedule
across writers. Five design changes (key shift, straight-through gates,
content input, recency prior, $\epsilon$-safe features) were made after the
proposal and before any baseline-vs-controller comparison; they apply to all
writers, but they were motivated by getting the controller to learn, and the
baselines were tuned only through the learning-rate grid of
Table~\ref{tab:hparams}. The task is
synthetic: results bound what allocation can do on associative recall and do
not establish language-model gains. Finally, the memory update is a sequential
loop over tokens, which limits the scale the sweep can reach.

\subsection{What changed between the proposal and the final experiment}
\label{sec:changes}

Every change is dated in the project's lab notebook; the ones that affect
interpretation are:
\begin{enumerate}
\item \textbf{Target settings.} The proposal's 64-association, 32-slot target
did not learn with the pilot's four layers and learning rate $10^{-3}$; two
layers and $3 \times 10^{-4}$, found by one-variable probes, became the frozen
backbone setting; each writer's learning rate was then selected on validation
(Table~\ref{tab:hparams}). Vocabulary 8192, 8000 steps and weight decay 0.1 were
kept.
\item \textbf{Capacity ceiling and the pair-only reference.} After the first
three-seed results at the target, the ceiling simulation showed the cell was
capacity-bound; the pair-only recency writer was added as the non-learned
reference, naive recency was kept as a control, and the hypotheses were moved
to 64 and 128 slots. The $N = 128$ column trains at length 1024 because its
context block does not fit in 512.
\item \textbf{Checkpoint selection.} Test evaluations use the checkpoint with
the best validation recall rather than the last, because the cosine tail moved
several controller runs into a worse write policy after their peak.
\item \textbf{Equal-learning-rate check.} Twelve runs between the two sweep
columns, with
each learned writer at the other's rate, replaced the best-of-each H2
comparison as the reported one.
\item \textbf{Input-only ablation.} A code audit after the sweep found the
pre-registered ablation still saw key novelty; a second ablation with that
feature zeroed was added, pre-registered, and run on the same cells and seeds.
\item \textbf{Re-selection.} The controller's learning rate and hidden size
were re-selected at the decisive cell on three seeds after the sweep; the
sweep's setting won, so no cell was re-run.
\item \textbf{Speed.} The per-timestep memory update was compiled and the
whole step captured as a CUDA graph, numerically identical to the eager loop
and 3.4 times faster; without it the sweep would not have fit the schedule.
\item \textbf{Scale.} The proposal's 20M-parameter backbone was not reached;
every run uses the two-layer 5.99M model that the probes showed learns the
task.
\item \textbf{Added after the sweep}, each pre-registered: the skewed-key
pilot (24 runs), the delay sweep (27 runs), the full-attention reference (3
runs), the input-only ablation at $N = 128$ (6 runs), and the gate replay that
measures in-place update handling. None changed a sweep number; each is
reported where it bears.
\end{enumerate}

\section{Conclusion}
\label{sec:conclusion}

This work asked whether a bounded memory beside a recurrent state should
decide what to store by looking at what is already stored. Under a protocol
fixed before the sweep, with 108 sweep runs on three seeds per cell and 60
follow-up runs, the answer on multi-query associative recall is no. A learned
controller with per-slot interference features loses to a parameter-free rule
that admits every key-value pair and nothing else, in every cell, by 6.6
points at the decisive 64-slot cell and by 16 to 33 points elsewhere, every
seed negative in every cell (H1 not supported anywhere, reversed in three
cells). The controller does beat the three baselines the proposal named, by
20 to 63 points above 32 slots, but H1 is defined against the strongest
other writer, and that is the rule. An ablation whose gate sees nothing
derived from the stored keys or values beats the controller at both $N = 64$
budgets and matches its best ablation, so the interference signal added no
information a learned gate used (H2 not supported, reversed at 64 slots). The
mechanism is measured, not inferred: the controller admits 69 to 82\% of pairs
where the rule admits all; the per-slot interference features lower admission
and widen the seed spread; key novelty moves recall by at most 2~pp; and no
learned writer ever overwrote an updated key in place, the one behaviour the
interference features were built to enable.

Three things the study establishes beyond the hypotheses. The proposal's
target cell is capacity-bound: the pair-only rule answers 40\% there by a
closed form, foreknowledge would add 10, and a capacity analysis that costs
seconds would have moved the target before any training run. The pair-only
rule is the bar: when queries are uniform over keys, stored content cannot
predict reuse beyond recognising an update, as the caching literature says,
so the only margins left to a learned policy are admission and in-place update
handling, and this rule, which does neither, is the best policy tested; a
learned admission policy for bounded memories should be reported against it. And one-seed hyperparameter selection in a cell that
cannot separate policies produced a false positive for H2 that survived the
sweep and fell only to an equal-learning-rate check; the re-selection on three
seeds at the decisive cell is what supports stating the negative result.

What the study does not rule out. The learned writers trained for a fixed
8000 steps, and in the skewed-key pilot the controller gained 18~pp between
4{,}000 and 12{,}000 steps; a longer matched schedule could narrow the 4 to
6-point gap between the best learned writer and the rule, though at the pilot
scale it did not close it. The baselines are simplifications of the cited mechanisms,
re-implemented without public code, and the residual cache in particular was
under-tuned above 32 slots. The task is synthetic, and its queries are
uniform over keys, which is exactly the regime where stored content cannot
predict reuse; the skewed-key pilot is one step toward the regime where it
can, and there the gate did learn to reject distractors on two of three seeds
and still trailed the rule by 1~pp on those seeds and 6~pp on the three-seed
mean.

The work was done because constant-cost inference buys a fixed state, and a
write rule that closed the recall gap would make bounded memory competitive
with a growing cache on the one task where the cache is known to win. It did
not find that rule; it found the bar such a rule has to clear, the margin
available to it, and the fact that looking at stored content, in the form
tested here, does not help.
